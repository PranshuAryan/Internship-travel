# Deploying to Vercel

Vercel supports Flask with zero required config — it detects the `app` instance in `app.py` automatically and runs it as a single Vercel Function. However, two things about Vercel's platform are different from Render/Railway and need handling:

## 1. Static files (already fixed in this project)

Flask's own static file serving (`app.static_folder`, and the `/static/...` URLs generated by `url_for('static', ...)`) is **ignored by Vercel**. Vercel only serves files placed in a top-level `public/` directory, matched to the same URL path.

This project already includes a `public/static/` folder that mirrors `static/` exactly, so the same `url_for('static', filename='css/style.css')` calls in the templates resolve correctly — Vercel's CDN serves them straight from `public/static/css/style.css` without needing any template changes.

> If you add or change any CSS/JS file, update it in **both** `static/` (used by Flask locally and on Render/Railway) and `public/static/` (used by Vercel).

## 2. Database persistence (you need to do this part)

Vercel Functions run on a **read-only filesystem** except for `/tmp`, and `/tmp` is wiped between invocations and isn't shared across instances. That means:

- SQLite (`sqlite:///travel.db`) will either fail to write, or silently lose all data between requests.
- Any bookings, registrations, or seeded trips will not reliably persist.

**Fix: use a free hosted Postgres database instead of SQLite when deploying to Vercel.**

1. Create a free Postgres database on [Neon](https://neon.tech) or [Supabase](https://supabase.com) (both have generous free tiers built for exactly this).
2. Copy the connection string they give you (looks like `postgresql://user:password@host/dbname`).
3. Add `psycopg2-binary` to `requirements.txt`:
   ```
   psycopg2-binary==2.9.9
   ```
4. In your Vercel project settings → Environment Variables, set:
   ```
   SQLALCHEMY_DATABASE_URI=postgresql://user:password@host/dbname
   SECRET_KEY=<a long random string>
   ```
5. Redeploy. On first deploy, you'll still need to create tables and seed data once — the easiest way is to run the same `db.create_all()` / `seed_mock_data()` one-liner from the README, but pointed at your Postgres URL, from your local machine (with `SQLALCHEMY_DATABASE_URI` in your local `.env` temporarily set to the same Postgres connection string).

## 3. If you still get a 404 after this

Vercel's `NOT_FOUND` page usually means the deployment build didn't produce a working function at all (rather than a normal Flask 404). Check:

- **Vercel dashboard → your project → Deployments → click the failed/latest deployment → "Build Logs" and "Function Logs" tabs.** This shows the actual Python error, which is much more specific than the generic 404 page.
- Confirm the **Framework Preset** in Project Settings is set to "Other" (or is auto-detected as Flask) — not "Create React App" or another static-site preset, which won't run Python at all.
- Confirm `requirements.txt` and `app.py` are both at the repository root (not nested in a subfolder), unless you've set `tool.vercel.entrypoint` accordingly.

## Recommended alternative

If you don't specifically need Vercel, Render or Railway (see the main `README.md`) run this app as a normal always-on server, so SQLite works out of the box with zero extra setup. Vercel's serverless model is a better fit for the app once it's using Postgres.
